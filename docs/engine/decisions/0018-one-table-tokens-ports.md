# 0018. Один стол, токены, порты отправки и таймера

**Контекст.** Движку нужна сеть: FastAPI WebSocket. Нужно было решить,
сколько игр держит процесс, как вернувшийся клиент доказывает, кто он, и
как прикладной слой отправляет сообщения и считает время, не зная ни о
сети, ни о часах.

**Решение.**

- Один запущенный движок — одна игра, **стол**.
- Сев за стол, игрок получает секретный **токен**; с ним новое
  соединение снова становится этим игроком.
- Прикладной слой объявляет два **порта**: отправитель и таймер.
  Адаптер реализует их на WebSocket и `asyncio`, тесты — заглушками.
  Рассматривался вариант без портов (стол возвращает, что отправить и
  какие таймеры завести) — отклонён, чтобы держаться гексагональной
  схемы.
- По проводу — JSON вида `{"type": ..., ...}`.

Формулировка — в [прикладном слое](../architecture/application/README.md)
и [адаптерах](../architecture/adapters/README.md).

**Последствия.** Прикладной слой тестируется без сети и без настоящего
времени. Чужой клиент не может выдать себя за игрока. Комнат и кодов игр
нет: чтобы сыграть две игры, запускают два движка.
